# 01-3 规划与纠错机制 (Loop & Workflow)：Agent 自主运行逻辑

在实际应用中，很多人容易把“工作流自动化（Workflow）”和“真正的智能体自主循环（Agent Loop）”混为一谈。

搞清楚两者的区别与协作机制，能帮你彻底明白为什么有的 AI 工具像“刻板的机器人流水线”，而有的 AI 工具却像“能够自我纠错的真人学长”。

---

## 1. 确定性工作流 (Workflow)：像火车跑在铁轨上

* **定义**：按人类提前编排好的固定分支与线性顺序执行的自动化流水线。
* **流程特征**：
  $$\text{步骤 A（抓取网页）} \longrightarrow \text{步骤 B（提取标题）} \longrightarrow \text{步骤 C（翻译成中文）} \longrightarrow \text{步骤 D（发送邮件）}$$
* **优势**：
  * **结果极其确定、速度飞快、费用极低**。每一步做什么完全由代码定死，不会出现大模型天马行空的幻觉。
* **致命缺陷**：
  * **缺乏容错与弹性**。如果步骤 A 遇到的网页稍微变动了排版结构，或者步骤 C 翻译接口偶尔超时，整个流水线就会立刻崩溃报错，完全无法“自主随机应变”。

---

## 2. 自主循环 (Agent Loop / ReAct)：带纠错能力的导航仪

真正的智能体不是僵化的流水线，它运行在一个被称为 **ReAct（Reasoning + Acting，推理与行动）** 的持续循环体系中（该理论由普林斯顿大学与谷歌团队于 2022 年提出，已成为现代 Agent 的工业标准）：

```text
       ┌─────────── 接收人类目标 ───────────┐
       │                                     │
       ▼                                     │
   [1. 观察现状] (读取环境状态、工具上次的报错)  │
       │                                     │
       ▼                                     │
   [2. 思考分析] (当前离目标还差多远？应该怎么走？)│
       │                                     │
       ▼                                     │
   [3. 决策行动] (调用工具执行，如重新写文件/搜网络)│
       │                                     │
       ▼                                     │
   [4. 判断完成？] ──(否：报错或未达到目标)─────┘
       │
       ▼ (是：任务通过验证)
   向用户汇报交付成果
```

### 真实大学场景：大创项目数据爬虫脚本调试
* **传统工作流**：
  * 跑了一下爬虫脚本，由于目标网站加了防盗链，报错 `403 Forbidden`，程序直接挂掉退出。
* **Agent 自主循环**：
  1. **观察**：看到终端抛出了 `403 Forbidden` 异常；
  2. **思考**：分析报错原因，推测是缺少请求头（User-Agent）或触发了频率限制；
  3. **行动**：修改 Python 代码，在请求头中伪装浏览器指纹，并加入 1~2 秒随机延迟；
  4. **再次观察**：重新运行脚本，发现返回了 `200 OK`，成功抓取到数据；
  5. **完成**：汇报“已成功解决反爬限制，数据已抓取并保存”。

---

## 3. 为什么必须给循环装上“刹车闸”？

虽然自主循环赋予了 Agent 惊人的自愈能力，但如果放任不管，它也会带来两大风险：

1. **死循环与算力浪费（烧钱陷阱）**：
   * 如果某个问题在客观上无法解决（比如目标网站已经彻底关停），没有限制的 Agent 可能会反复重试几十次，不断疯狂向大模型发起请求，几分钟内烧光你的账户余额。
   * **防护机制（最大步数限制）**：成熟的 Agent 框架通常会硬性限制最大步数（如单次任务最多循环 10 或 15 步），超时或超步数自动熔断并向人类求助。
2. **破坏性高危动作拦截（权限护栏）**：
   * 在自主尝试解决报错的过程中，Agent 可能会做出过激反应（例如：“既然依赖冲突，我干脆把整个系统环境删了重装”）。
   * **防护机制（人类在环 / Human-in-the-loop）**：对于涉及“删除文件、系统重启、扣款支付、向外发送信息”等高危动作，必须通过弹窗或确认提示暂停循环，必须人类亲自输入确认才能继续。

---

## 4. 总结：两者的最佳组合形态

在当今高效的 AI 工具中，通常不是“非此即彼”，而是将两者结合：
* **用 Workflow 定大框架**：先做数据预处理，再做大模型分析，最后做格式导出；
* **在复杂的局部节点用 Agent Loop 攻坚**：在面对多变、容易出错的局部子任务（如解析非标准格式的文档、修复代码片段）时，交由 Agent 自主规划与纠错。

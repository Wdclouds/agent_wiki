# 05-1 常见报错现象与自救排查表

使用各类 AI Agent 和开源工具时，报错是必然会经历的过程。遇到红色错误不要慌张，绝大多数问题都集中在“网络、凭据、依赖、并发”这几个固定方向。

本篇整理出高校新手发生率最高的 6 类经典报错及一键排查方案。

---

## 1. 经典报错速查矩阵

| 报错关键词 / 现象 | 核心根因 | 30 秒自救动作 |
| :--- | :--- | :--- |
| `ConnectTimeout`<br>`Connection refused`<br>`WinError 10061` | 终端/脚本未走代理，或代理软件未开启 | 检查代理客户端是否正常运行；在终端重新执行 `$env:HTTP_PROXY` 注入命令 |
| `401 Unauthorized`<br>`AuthenticationError`<br>`Incorrect API key` | API Key 错误、已过期，或前后带有非法空格 | 登录模型控制台重新生成 Key；检查 `.env` 文件中是否误加了中文引号或空格 |
| `429 Too Many Requests`<br>`RateLimitError`<br>`Insufficient Quota` | 触发调用频次上限，或账户余额已经见底 | 检查云平台账户余额是否欠费；如果是免费模型，降低并发频率（在请求间休眠数秒） |
| `ModuleNotFoundError`<br>`No module named 'xxx'` | Python 环境中未安装对应依赖库 | 在终端执行 `pip install xxx`（或 `uv pip install xxx`），建议切换国内清华源安装 |
| `无法加载文件...因为在此系统上禁止运行脚本` | Windows PowerShell 默认执行策略拦截 | 运行 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` 解除限制 |
| `JSONDecodeError`<br>`Output parsing failed` | 大模型输出格式崩坏，未按 JSON 返回结构 | 模型意图理解能力偏弱；建议切换更强推理模型（如 DeepSeek-V3/R1），或在提示词中追加“必须严格输出合法 JSON” |

---

## 2. 深度自救三板斧

如果遇到的报错不在上述列表中，请按照以下三个标准步骤排查：

### 第一步：看日志的最底部（抓核心原因）
* Python 或 Node.js 抛出的异常调用栈（Traceback）往往有二三十行，最上面的通常只是层层调用的外壳；
* **永远直接滑到日志的最后 1~3 行**，真正的错误类型（如 `FileNotFoundError: data.csv`）永远写在最底下。

### 第二步：检查 Base URL 与模型名是否匹配
许多兼容 OpenAI 格式的工具经常报错 404 或 Not Found：
* **常见原因**：Base URL 末尾漏写或多写了 `/v1`；
  * 正确格式通常为：`https://api.deepseek.com/v1` 或 `https://dashscope.aliyuncs.com/compatible-mode/v1`；
* **模型名拼写错误**：
  * 例如将 `deepseek-chat` 错拼为 `deepseek-v3`，或者将 `qwen-plus` 错拼为 `qwen_plus`。请务必去对应云平台的官方文档中核对确切的模型调用名称。

### 第三步：Agent 陷入死循环时的“紧急制动”
* 当你发现控制台在同一个错误上反复打转、持续几分钟一直在输出相同重试日志时：
* 立即在终端键盘按下 **`Ctrl + C`** 强行中断程序；
* 检查你的任务提示词是否缺乏收敛条件，或者检查要处理的目标文件是否由于损坏而导致 Agent 永远无法解析。

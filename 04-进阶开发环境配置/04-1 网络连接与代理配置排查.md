# 04-1 网络连接与代理配置排查

在高校内使用海外 AI Agent 工具、下载开源代码或调用海外大模型 API 时，国内新手遇到的**第一个、也是发生率最高的崩溃点**就是：**网络连接报错**。

最经典的困惑莫过于：“*我的浏览器明明能正常打开 Google 和网页版 ChatGPT，为什么一在终端里运行 Agent 就报 Connection Refused 或 Timeout？*”

---

## 1. 为什么“网页能用，命令行和 Python 却不能用”？

这是绝大多数非计算机专业新生的认知盲区：
* **普通网络工具默认只接管浏览器流量（即 Windows 系统代理）**；
* 而操作系统的**终端命令行（CMD、PowerShell、Git Bash）以及 Python 脚本，默认完全不走系统代理**！
* 只要你的命令行工具尝试向海外服务器（如 GitHub、Anthropic、OpenAI）发起请求，它就会直接绕过代理走国内直连线路，最终因网络无法直达而超时崩溃。

---

## 2. 终端代理一键注入法（临时且安全）

解决办法非常直接：在运行任何 Agent 工具之前，在同一个终端窗口里输入两行命令，告诉终端走本地代理端口。

### 第一步：找到你本地客户端的“本地监听端口”
打开你电脑上正在运行的网络客户端（如 Clash、v2rayN、Mihomo、Sing-box 等），在设置中查看“混合代理端口（Mixed Port）”或“HTTP 代理端口”：
* **常见默认端口**：
  * Clash / Mihomo 系列通常为：`7890`
  * v2rayN 通常为：`10809`
  * Nekoray 通常为：`2080`

### 第二步：在终端注入环境变量

#### PowerShell（Windows 推荐）
复制以下两行直接粘贴回车：
```powershell
$env:HTTP_PROXY="http://127.0.0.1:7890"
$env:HTTPS_PROXY="http://127.0.0.1:7890"
```

#### Git Bash / WSL / macOS / Linux
```bash
export http_proxy="http://127.0.0.1:7890"
export https_proxy="http://127.0.0.1:7890"
```

> 💡 **重要常识**：  
> 上述命令**只对当前打开的这个黑色终端窗口生效**。一旦关掉该窗口，设置自动失效，绝不会搞乱你电脑全局的网络配置。

---

## 3. 如何验证终端网络真的“通了”？

在配置了上述命令的同一个终端里，输入以下测试命令：
```powershell
curl -I https://www.google.com
```
* **成功现象**：屏幕返回类似 `HTTP/2 200` 或 `HTTP/1.1 200 OK`，说明终端已具备顺畅的网络访问能力；
* **失败现象**：光标卡住不动数秒后报 `Failed to connect`，说明端口填错，或者本地客户端未开启“允许局域网连接”。

---

## 4. 常见报错对照与救急方案

| 报错关键词 | 真实原因 | 根治方案 |
| :--- | :--- | :--- |
| `ConnectTimeout` / `Connection refused` | 终端直连失败，未设置代理或端口号填错 | 检查代理客户端运行状态与端口号，重新执行 `$env:HTTP_PROXY` |
| `SSL: CERTIFICATE_VERIFY_FAILED` | 代理软件的 HTTPS 证书拦截或解密冲突 | 在代理客户端中开启“TUN 模式（虚拟网卡模式）”，或者配置跳过 SSL 校验 |
| `403 Forbidden` / `User location not supported` | 代理节点所在的地理区域被服务商封锁 | 某些服务（如 OpenAI/Claude）屏蔽了香港节点，请在代理客户端中将节点切换至**美区、日区或新加坡** |

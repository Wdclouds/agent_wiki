# 02-3 费用控制与安全规范：账单限额设置与防泄露手册

在高校学生接触 API 与 Agent 的过程中，最令人后怕的不是工具报错，而是**“一不小心收到巨额扣费账单”**或**“辛辛苦苦充值的 Key 被黑客盗刷”**。

这并不是危言耸听。每年都有学生因为将带有 API Key 的代码上传到公开代码仓库，几分钟内被全网扫描爬虫盗刷数百甚至数千美元。
本篇为你总结高校学生必须遵守的**“钱包安全三定律”**与防盗刷实操方案。

---

## 1. 钱包安全第一定律：永远采用“预付费充值”，拒绝盲目绑定自动划扣信用卡

* **核心原则**：
  * **国内平台（推荐）**：如 DeepSeek 官方、阿里云百炼、硅基流动等，普遍支持**支付宝/微信预充值**。每次只充值 **5 元或 10 元**。
  * **机制保障**：预付费模式下，账户余额一旦耗尽，系统只会返回 `Insufficient Balance`（余额不足）并立即停止调用，**绝不可能产生负债或透支账单**。
* **海外平台防坑（如 OpenAI / Anthropic）**：
  * 海外平台通常强制绑定支持外币的双币信用卡，并默认开启“自动续费（Auto-Recharge）”。
  * **必须动作**：进入控制台的 `Settings -> Billing -> Usage limits`，将 **Monthly Hard Limit（每月硬性消费上限）** 强制设定为安全阈值（例如 $5 或 $10 美元），一旦触发立刻切断请求，严禁不设上限裸奔。

---

## 2. 钱包安全第二定律：严禁将 Key 明文写入代码，更严禁提交至公共平台

互联网上存在大量专门 24 小时巡检公开 GitHub 仓库的自动化爬虫。只要你在公开代码里敲入了一串 `sk-xxxxxxxx` 并执行了 `git push`，**平均在 15~30 秒内**该密钥就会被黑客捕获并接入黑产代理池进行高并发疯狂消耗。

### 危险操作禁区
* ❌ 严禁把带有实际 Key 的脚本截图发在班级群、QQ 群、微信群；
* ❌ 严禁在提交课程作业或大创项目代码时，把包含 Key 的文件打包提交到公网 Git 平台或网盘；
* ❌ 严禁将 API Key 借给他人做批量爬虫或未知用途的测试。

### 标准安全姿势：使用 `.env` 环境变量文件
所有成熟的开源 Agent 均支持从系统环境变量或 `.env` 文件中隐式读取密钥：
1. 在项目根目录下创建名为 `.env` 的纯文本文件，写入：
   ```env
   DEEPSEEK_API_KEY=sk-your-real-key-here
   ```
2. 立即在项目根目录的 `.gitignore` 文件中添加一行：
   ```text
   .env
   ```
   （这样 Git 在备份和推送代码时，会自动完全忽略该文件，确保隐私卡密永远留在你自己的电脑本地）。

---

## 3. 钱包安全第三定律：不同工具分权建 Key，闲置密钥立即注销

* **专 Key 专用，不混用一个母 Key**：
  * 在云厂商控制台创建 API Key 时，务必给每个 Key 写清描述备注：
    * 例如创建 `Key_For_CherryStudio`（专门给日常桌面助手用）；
    * 创建 `Key_For_CodeAgent`（专门给编程测试用）。
* **被盗或泄露后的“一秒止损法”**：
  * 只要你怀疑自己的 Key 曾经发给过别人、或者不慎推送到了公网：
  * **不要犹豫，立即登录对应云平台控制台，点击“Revoke（吊销）/ Delete（删除）”！**
  * 原密钥删除后，之前的卡密瞬间作废，黑客的任何后续请求都会被服务器直接拦截。随后重新生成一个新的 Key 换上即可。

---

## 4. 防“死循环”无限烧钱的安全习惯

除了被盗，另一大常见的烧钱诱因是：**写错循环逻辑，导致 Agent 陷入死循环反复请求模型**。

* **自检三件事**：
  1. 运行本地开源 Agent 前，确认配置文件中的 `max_iterations`（最大迭代步数）已设置上限（通常推荐设为 10~15 步）；
  2. 第一次在终端运行长链条 Agent 时，在旁边盯 1~2 分钟，观察终端输出的调用日志是否正常推进；
  3. 看到控制台在同一个错误上连续打转重试超过 3 次，果断在键盘按下 **`Ctrl + C`** 紧急刹车终止程序，排查原因后再试。
